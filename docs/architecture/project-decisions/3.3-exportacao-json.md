# Decisão 3.3 — Exportação local em JSON

**Data:** 20/11/2026  
**Responsável:** Aria (@architect)  
**Story:** `docs/stories/3.3.exportacao-json.md`  
**Estado:** aceita para implementação; gates e validação de qualidade serão registrados pelo QA.

## Origem e recorte

O item 2.2 de `documentos/Segunda entrega - Roteiro PI IV  - Desenvolvimento para dispositivos móveis.pdf` exige botão no aplicativo para gerar JSON. O usuário manteve a exportação e dispensou o dashboard. A Story 3.3 reutiliza o cache entregue pelas Stories 3.1/3.2; não adiciona dashboard, chamada de rede, rota no servidor ou alteração de banco.

## Contrato e privacidade

Um serializador puro recebe o snapshot carregado, a identidade demonstrativa atual apenas para seleção e o instante de geração. Produz formato versionado (`version: 1`), instante ISO, contexto demonstrativo, catálogo local e somente carrinho, biblioteca e último pedido da conta selecionada. Dados ausentes são listas vazias e pedido nulo. O instante é injetável para testes reproduzíveis.

A saída contém campos explicitamente permitidos: identidade do produto, nome, tipo, descrição, loja de ativação e compatibilidades, preços e totais em centavos. Converter valores monetários por arredondamento consistente e validar inteiros seguros; recomputar totais dos itens exportados, sem confiar em rótulos formatados ou totais transitórios. Valores incompatíveis provocam erro de geração, nunca JSON monetário silenciosamente inválido.

Metadados identificam origem local, condição de sincronização e contagem de operações pendentes, sem afirmar que o cache foi confirmado pelo servidor. A outbox fornece apenas indicadores agregados necessários; seus payloads, identidade de ator e revisões internas não integram o arquivo. Se houver contagem específica da conta, selecionar pela conta atual sem divulgar dados de outras contas. Um catálogo legado ainda não reconciliado permanece identificado como pendente mesmo sem operações recuperáveis na fila.

Não exportar identidade pessoal/credenciais do usuário, token, sessão, formulários, dados financeiros, chaves de ativação ou registros de outros usuários. Não serializar diretamente o snapshot nem reutilizar o objeto de produto inteiro por espalhamento: o contrato exportável possui lista própria de campos. A exportação não marca operações como sincronizadas nem altera o estado persistido.

## Entrega por plataforma

- **Android/iOS:** usar `expo-file-system ~19.0.24` e `expo-sharing ~14.0.8`, versões do mapa local do SDK 54. Verificar `Sharing.isAvailableAsync()`, criar arquivo `.json` com nome próprio em `Paths.cache` por `new File(...)`, `create()` e `write()`, e chamar `Sharing.shareAsync` com MIME `application/json` e UTI `public.json`. A API moderna `File` evita misturar chamadas legadas de filesystem no caminho novo. Escrita e abertura da folha de compartilhamento não comprovam envio ou salvamento pelo aplicativo de destino.
- **Web:** usar adaptador de plataforma com `Blob` de MIME JSON, URL de objeto e âncora com atributo `download`. Acionar o download e remover a âncora; revogar a URL após o navegador poder consumi-la. Não usar `expo-sharing` para URI de arquivo local na web, pois esse fluxo não é suportado pelo SDK.

O nome identifica PixelVault, instante de geração e extensão `.json`, sem nome, e-mail, ID de conta ou segredo. Evitar colisão de arquivos em exportações sequenciais. O caminho nativo é cache temporário, não garantia de backup persistente.

## Integração e verificação

O botão aparece no catálogo e na administração, reaproveitando componentes existentes. A inicialização deve terminar antes de habilitar exportação. Bloquear concorrência com referência síncrona além do estado visual ocupado, liberando ambos em `finally`. Falhas de serialização, escrita ou indisponibilidade de compartilhamento recebem feedback claro. Ao retornar da folha nativa, usar mensagem neutra sobre encerramento/abertura do compartilhamento, sem declarar que um terceiro recebeu o arquivo; fechar a folha não é falha.

Testes puros verificam contrato, centavos, vazios, isolamento e exclusão de segredos. E2E web deve baixar e ler o arquivo real, incluindo cenário offline. Testes de adaptador e exportação Android não equivalem à execução nativa de escrita e compartilhamento: ausência de aparelho/emulador permanece ressalva explícita. Nenhuma mudança arquitetural adicional é necessária para este incremento.
