## Story

**Como** usuário do PixelVault,  
**quero** gerar um arquivo JSON pelo aplicativo com os dados locais pertinentes à minha conta demonstrativa,  
**para que** eu possa consultar e compartilhar uma exportação estruturada mesmo sem conexão.

## Contexto e fontes

O roteiro exige um botão para gerar dados em JSON. A resposta JSON da API não substitui o arquivo acionado no aplicativo. O usuário dispensou o dashboard e definiu pitch em vídeo; ambos permanecem fora deste incremento.

## Acceptance Criteria

1. Existe botão de exportação acessível nos fluxos de catálogo/admin, utilizando o cache local carregado. A exportação funciona sem chamar API nem exigir conexão e fica indisponível enquanto os dados iniciais não estiverem prontos.
2. O arquivo é JSON válido, com versão do formato, instante de geração em ISO e contexto explicitamente demonstrativo. Inclui catálogo atual e somente carrinho, biblioteca e último pedido da conta demonstrativa atual; ausência de dados é representada por listas vazias/pedido nulo.
3. Preços e totais exportados usam inteiros em centavos, com conversão consistente e sem perda de precisão. Produtos preservam identidade, tipo, loja de ativação e compatibilidades; totais são coerentes com os itens exportados.
4. Os metadados distinguem dados locais de dados confirmados no servidor e informam contexto/quantidade de sincronizações pendentes. Não apresentam catálogo offline ou alteração pendente como dado remoto confirmado.
5. A serialização usa lista explícita de campos permitidos. Nunca inclui senhas, formulários de acesso/pagamento, sessão, token, chaves de ativação, dados de outro usuário ou payloads da outbox. O snapshot interno completo não é exportado diretamente.
6. Em Android/iOS, o aplicativo cria arquivo com APIs compatíveis com Expo SDK 54 (`expo-file-system ~19.0.24`) e abre o compartilhamento do sistema (`expo-sharing ~14.0.8`). Versões e APIs são conferidas na documentação oficial versionada antes da implementação.
7. Na web, a ação cria um Blob e provoca download real de arquivo `.json`, com nome identificável e revogação dos recursos temporários após o uso. O arquivo baixado contém o mesmo contrato lógico da versão nativa.
8. A ação apresenta estado ocupado e impede cliques duplicados concorrentes. Falhas de geração, escrita ou compartilhamento indisponível exibem mensagem clara sem falso sucesso. Fechar o compartilhamento não é tratado como falha nem como comprovação de envio a outro aplicativo.
9. Testes unitários cobrem contrato, valores em centavos, dados vazios, isolamento de usuários e filtragem de campos sensíveis. E2E web aciona o botão, captura o arquivo realmente baixado e valida seu conteúdo, inclusive com API indisponível.
10. Lint, typecheck, suíte completa e build Android passam. Evidências e File List são atualizadas. Se não houver aparelho/emulador, a verificação nativa de escrita/compartilhamento permanece explicitamente pendente; build ou E2E web não a substituem.
