## Story

**Como** usuário do PixelVault,  
**quero** um roteiro simples de instalação e um iniciador Windows por duplo clique,  
**para** abrir a aplicação web conectada à API sem preparar manualmente vários terminais.

## Contexto e fontes

- Solicitação atual do usuário: instruções do zero e automação da execução.
- `package.json`: Expo SDK 54, scripts npm, API Node e verificações existentes.
- `scripts/init-db.mjs`: inicialização que recria o banco; o iniciador só poderá chamá-la quando o destino ainda não existir.
- `server/config.mjs` e `.env.example`: configuração da API e credenciais privadas opcionais do Checkout Pro de teste.
- `README.md`: comandos, contas de demonstração e portas de execução atuais.

## Acceptance Criteria

1. Disponibilizar `Iniciar-PixelVault.cmd` na raiz, executável por duplo clique no Windows, inclusive quando a pasta contiver espaços. Verificar Node.js 22.13 ou superior e npm; orientar instalação quando ausentes ou incompatíveis. Um `.cmd` com Node instalado atende à automação solicitada, sem prometer um `.exe` independente.
2. Instalar as dependências com `npm ci` quando `node_modules` não existir. Falhas de instalação ou dependências incompletas produzem mensagem clara, sem continuar como se a preparação tivesse passado.
3. Iniciar API e Expo web localmente, configurar `EXPO_PUBLIC_API_URL` para a API iniciada e abrir o navegador. Aguardar a API estar pronta antes de anunciar a aplicação disponível; manter os registros visíveis para diagnóstico.
4. Criar o banco e catálogo apenas quando o arquivo configurado não existir. Reutilizar bancos existentes e suas migrações normais, sem recriação, limpeza ou substituição dos dados do usuário.
5. Permitir execução local sem credenciais do Mercado Pago. Quando utilizado, o arquivo privado `.env.mercadopago` é carregado exclusivamente no backend e mantém o modo de teste; tokens não são impressos, incluídos no frontend ou copiados para documentação.
6. Detectar portas ocupadas e falhas de inicialização, sem encerrar processos de terceiros. Ao sair com Ctrl+C, encerrar os processos iniciados pelo próprio lançador e informar como parar a execução no guia.
7. Entregar guia em português com instalação do Node, abertura do projeto, primeiro e próximos usos, URLs locais, contas jogador/administrador, Mercado Pago opcional, parada, solução de problemas e alternativa manual. Vincular o guia no README.
8. Executar lint, typecheck e suíte completa, além de smoke real com banco temporário: bootstrap, API saudável, catálogo e frontend acessíveis, reinício preservando dados, conflito de porta e encerramento. Registrar resultados e limites sem afirmar testes não realizados. Atualizar checklist e File List antes de encerrar.
