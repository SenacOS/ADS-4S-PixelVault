## Story

**Como** equipe de desenvolvimento do PixelVault,
**quero** validar e organizar a base existente em React Native com Expo SDK 54, com estrutura enxuta e instruções reproduzíveis,
**para que** os Prompts 11 e 12 possam implementar e demonstrar as interfaces e interações da Sprint 1 em um ambiente comum, sem ampliar o escopo aprovado.

## Contexto e valor

Esta story materializa o recorte do Prompt 10 e a primeira parte da história técnica `HT-01`. Ela deve produzir uma base móvel comprovadamente instalável e executável, mas não deve antecipar a implementação completa das telas, da navegação funcional ou das interações previstas nos Prompts 11 e 12. O valor desta entrega é remover incertezas de ambiente, fixar uma organização simples e deixar comandos e evidências que outro integrante consiga reproduzir.

Dependências documentais atendidas: Prompts 3, 6, 8 e 9. A especificação revisada A09, versão 1.0, prevalece sobre A08, versão 0.2, em qualquer divergência. Não há story local anterior; por isso, conforme o fluxo AIOX, esta é a primeira story (`1.1`).

## Acceptance Criteria

1. O projeto existente é auditado antes de qualquer alteração, e a entrega registra as versões reais do Node.js, npm, Expo, React e React Native usadas na validação, distinguindo claramente versões instaladas, versões declaradas e versões apenas recomendadas.
2. O projeto permanece em JavaScript e usa Expo SDK 54; qualquer ajuste de versões ou configuração é compatível com a documentação oficial versionada exigida em `AGENTS.md`, sem migração não solicitada para TypeScript ou outro framework.
3. A entrada do aplicativo compila e inicia sem erro bloqueante no ambiente documentado. A evidência informa comando executado, data, plataforma/alvo, resultado real e eventual limitação; uma tela estática ou o wireframe, isoladamente, não conta como evidência de execução.
4. O código do aplicativo adota uma estrutura pequena e compreensível que separa, no mínimo, telas, componentes reutilizáveis, dados fictícios e integrações. A estrutura é documentada no README e não introduz camadas, padrões ou pastas sem uso ou justificativa.
5. As dependências de execução e desenvolvimento são mantidas no mínimo necessário para esta story. Toda dependência adicionada ou mantida além do núcleo Expo/React Native é justificada de forma objetiva; Redux, microsserviços, autenticação de produção, infraestrutura de produção e integração real de pagamento não são adicionados.
6. Existe um `README.md` curto com pré-requisitos, instalação limpa, inicialização, alternativas reais de demonstração disponíveis no ambiente, comandos de qualidade e solução dos problemas efetivamente encontrados. Um integrante deve conseguir reproduzir o fluxo a partir de um clone e do arquivo de lock.
7. A base fica preparada para verificação em orientação retrato nas referências `390 × 844 px`, largura intermediária de `360 px` e `320 × 568 px`. O README identifica também os critérios futuros de área segura, ausência de rolagem horizontal, rolagem vertical quando necessária, toque mínimo de `44 × 44 dp`, teclado e fonte ampliada a pelo menos `130%`, sem declarar esses testes como aprovados antes das telas dos Prompts 11 e 12 existirem.
8. As correções `COR-01` a `COR-06`, os critérios `RESP-01` a `RESP-16` e os casos `UXT-01` a `UXT-14` ficam referenciados como restrições obrigatórias para a continuidade. Nesta story, apenas os itens aplicáveis à configuração e à preparação do ambiente são verificados; os casos funcionais dependentes das interfaces permanecem explicitamente pendentes.
9. Os comandos `npm run lint`, `npm run typecheck`, `npm test` e `npm run build` existem e são executados. Os resultados reais são registrados na story pelo agente de desenvolvimento; falhas não podem ser omitidas nem descritas como sucesso.
10. Problemas encontrados são registrados somente após observação real, com sintoma, comando/contexto e tratamento adotado ou pendência. Se nenhum problema for observado, o registro deve dizer isso expressamente, sem inventar ocorrências para preencher a seção.
11. O trabalho permanece limitado ao Prompt 10: não implementa a jornada funcional completa, CRUD, checkout, persistência, API Node ou Mercado Pago real, e não declara `HT-01`, `HT-02` ou `UXT-01` a `UXT-14` integralmente concluídos sem as evidências correspondentes.
12. A lista de arquivos e as notas de conclusão da story são atualizadas antes da passagem para revisão; alterações preexistentes e fora do escopo no worktree são preservadas.
